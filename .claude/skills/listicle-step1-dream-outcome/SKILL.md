# Шаг 1: Dream Outcome — Какой результат хочет получить покупатель?

## Суть шага

Это единственный шаг всей listicle-цепочки, который полностью заполняет человек. Задача — получить конкретную, ясную формулировку желаемого результата аудитории и зафиксировать базовые параметры ниши, которые понадобятся дальше: Шагу 2 (Persona + Awareness) для запуска persona research, и Шагу 3 (анализ продуктовой страницы) для контекста.

Конкурентную разведку этот шаг делает **облегчённо**, не подробно: полноценный конкурентный ресерч всё равно происходит внутри Шага 2, когда он запускает `user-persona-research` (у него свой отдельный поток «конкуренты + отзывы»). Дублировать эту работу здесь не нужно — трать время на саму формулировку Dream Outcome, а не на второй конкурентный ресерч.

## Алгоритм выполнения

### 1.1 Получить Dream Outcome от пользователя

Запроси у пользователя формулировку желаемого результата целевой аудитории. Подчеркни: нужна формулировка **от лица покупателя**, а не от лица бренда/эксперта.

Если пользователь уже дал Dream Outcome — переходи к п. 1.2.

### 1.2 Оценить качество формулировки

Проверь формулировку по критериям. Примеры ниже покрывают и услуги, и физический товар/ecom — под адверториал обе категории равноценны:

| Критерий | Хорошо | Плохо |
|----------|--------|-------|
| Конкретность | «Убрать запах изо рта у собаки без похода к ветеринару за 4 недели» | «Улучшить здоровье собаки» |
| Перспектива покупателя | «Я хочу перестать бояться, что дома есть невидимая утечка газа» | «Мы производим детекторы CO» |
| Измеримость | «Сфокусироваться на работе без рецептурных стимуляторов» | «Улучшить продукт для фокуса» |

Если формулировка размытая — задай уточняющие вопросы:
- «Какой конкретный результат хочет получить ваш покупатель?»
- «Как покупатель поймёт, что результат достигнут? Есть ли цифры/сроки/ощущения?»
- «В какой нише/категории продукт?»
- «Это физический товар, подписка или услуга?»

### 1.3 Зафиксировать дополнительный контекст

Уточни у пользователя (если не очевидно из Dream Outcome):
- **Ниша/категория** — в какой индустрии/товарной категории
- **География** — регион/рынок (влияет на язык поиска аудитории в Шаге 2)
- **Язык адверториала** — на каком языке будет финальный текст
- **Продукт уже существует?** — если да, есть ли уже готовая продуктовая страница (пригодится на Шаге 3), или её ещё нет

### 1.4 Лёгкая разведка ниши (web search)

Два коротких запроса — не больше. Цель не найти всех конкурентов (это сделает Шаг 2), а понять контекст рынка и собрать несколько узнаваемых имён брендов для Шага 2 (Метод 1 — FB Ads Library требует именно имена брендов, не URL лендингов).

**Запрос 1:** `[ниша] + рынок + тренды + [год]`
- Цель: понять текущее состояние рынка, ключевые тренды — 2-3 предложения для контекста

**Запрос 2:** `[ниша] + [продукт] + топ бренды / лучшие`
- Цель: собрать 3-5 узнаваемых имён брендов в категории (не лендинги, просто названия) — их можно будет проверить в FB Ads Library на Шаге 2, если этот метод выберут

Если пользователь уже знает своих ключевых конкурентов — просто спроси имена, не трать на это поиск.

```
РЕЗУЛЬТАТ ШАГА 1:
━━━━━━━━━━━━━━━━━
Dream Outcome: [формулировка]
Ниша/категория: [название]
Тип продукта: [физический товар / подписка / услуга / цифровой]
География: [регион/рынок]
Язык адверториала: [язык]
Продуктовая страница: [есть, URL известен позже (Шаг 3) / ещё не существует]

Известные бренды в категории (для Шага 2, метод FB Ads Library):
  1. [название]
  2. [название]
  ...
━━━━━━━━━━━━━━━━━
```

## Переход

После фиксации результата — переходи к **Шагу 2** (`listicle-step2-persona-awareness`: Persona Research → Awareness Ladder уровней 0-1 → выбор метода разработки).

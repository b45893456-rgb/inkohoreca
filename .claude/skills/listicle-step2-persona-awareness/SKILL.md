# Шаг 2: Persona → Awareness (уровни 0-1) → Метод

Этот скилл самодостаточен: он не вызывает другие скиллы и не требует ничего, кроме `WebSearch` (и субагентов, если они доступны — тогда шаг 2.2 можно распараллелить). Вся методология research'а и построения лестницы осознанности — ниже, целиком.

**Опционально, если пользователь просит больше глубины:** в проекте есть два отдельных, более полных скилла на тот же research — `listicle-user-persona-research` (полноценный ресёрч с 4 параллельными потоками и .docx на выходе вместо 3-5 персон текстом) и `listicle-hunt-awareness-ladder` (полная лестница на все 5 уровней, а не только 0-1, плюс сверка с текущей рекламной библиотекой Meta). Это не часть обязательной цепочки — предлагай их только если пользователь явно просит более глубокий/полный артефакт (например, «нужен документ для клиента» или «хочу видеть все 5 уровней, не только холодные»). По умолчанию используй встроенную лёгкую версию ниже — для 90% прогонов её достаточно.

## Суть шага

Адверториал работает с холодной аудиторией — с людьми, которые либо не знают о своей проблеме (Unaware), либо знают о проблеме, но не знают о решении (Problem Aware). Это единственные два уровня, которые адверториал реально закрывает: как только человек Solution Aware или Product Aware, ему нужна не статья, а сравнение и оффер (это уже зона продуктовой страницы, Шаг 3-4).

Шаг делает три вещи по порядку: понимает, из кого состоит аудитория (persona research) → для ОДНОЙ выбранной персоны прицельно раскладывает уровни 0-1 → решает, каким методом вытаскивать эти боли в текст, до того как идти анализировать продуктовую страницу (Шаг 3), потому что от метода зависит, что там искать.

## Входные данные

Из Шага 1: Dream Outcome, ниша/категория, тип продукта, география, язык.

## Часть A — Persona Research

### 2.1 Уточняющие вопросы

Прежде чем искать — задай пользователю через `AskUserQuestion` короткие вопросы (адаптируй под нишу, но обычно это):

1. **Ценовой/качественный сегмент** — масс-маркет / средний+ / премиум / любой
2. **Подкатегория продукта** — 2-4 варианта в рамках ниши из Шага 1
3. **Кто покупатель** — сам пользователь продукта / тот, кто выбирает за другого (напр. владелец собаки, родитель) / оба
4. **Цель ресёрча** — под конкретный запуск рекламы (нужны точные боли и триггеры) или общее понимание аудитории

Не пропускай этот пункт — без него персоны получаются «средняя температура по больнице» и не дают материала для хуков.

### 2.2 Research: добыча реального языка аудитории

Цель — не общие маркетинговые фразы («хочу чувствовать себя лучше»), а то, что человек реально пишет в поиске или на форуме. Ищи по нескольким источникам параллельно (если есть субагенты — запусти их в одном сообщении, чтобы не ждать по очереди):

- **Конкуренты + отзывы** — 5-8 брендов/продуктов в категории → их отзывы (Amazon, Trustpilot, локальные отзовики), особенно полезны для возражений и сравнений
- **Форумы и Reddit-аналоги** — реальные, неотфильтрованные боли. Для Reddit используй `WebSearch` обычной фразой, без операторов `site:`/точных кавычек — поисковик их часто игнорирует и возвращает пусто. Если ниша не покрыта Reddit — используй функциональный аналог (тематические форумы, локальные сообщества)
- **Quora / отраслевые блоги / медиа** — экспертные наблюдения, Q&A-психология, обзорная пресса
- **Локальный контекст** — форумы/сообщества на языке гео из Шага 1, если он не английский — там часто другой пласт возражений и культурного контекста

**Как формулировать запросы:** обычной поисковой фразой, не оператором. Плохо: `"reddit product X complaints forum 2024 2025"` (слишком много кавычек и мусора — вернёт пусто). Хорошо: `product X real reviews complaints does it actually work 2025`. Если прямых цитат нет — расшир запрос до общей темы и вытащи цитаты из статей/блогов, которые сами цитируют форумы/отзывы.

**Что считается хорошей цитатой:**
- Конкретная, не обобщённая («мой парикмахер спросил, не больна ли я» лучше, чем «у меня выпадают волосы»)
- Эмоционально окрашена словами самого человека, не маркетолога
- Для состояния до осознания проблемы — про состояние, не про решение
- Для момента, когда проблема уже осознана — реальная формулировка поискового запроса или вопроса

5-8 цитат на источник достаточно — точность важнее объёма. **Никогда не выдумывай цитаты и не приписывай источник, которого не проверял** — если ниша скудно покрыта, скажи об этом прямо, не заполняй пробел фантазией.

### 2.3 Синтез персон

Кластеризуй собранный материал по **эмоциональной/мотивационной оси**, не по демографии — «женщины 25-35, доход $50k+» это не персона, это аудитория для таргетинга. Хорошая персона организована вокруг конкретного эмоционального состояния/триггера покупки.

Собери 3-5 персон. Для каждой:

- **Название** — короткая ёмкая фраза + архетип в скобках (напр. «"Больше так не могу" (The Burnt-Out Fixer)»)
- **Profile** — 5-6 буллетов: пол/возраст, доход, гео, привычки, что триггерит, психотип
- **Real Voices** — 3-4 цитаты из п. 2.2 с указанием источника (форум/отзыв/Reddit-аналог)
- **Language Bank** — таблица: *Fear Phrases* (чего боится, своими словами) / *Objections* (что останавливает от покупки) / *Что убеждает* (конкретные рычаги, которые сработали в найденном материале)

Покажи список пользователю коротко (по 1-2 строки на персону) — это войдёт в п. 2.4.

## Часть B — Awareness Ladder (только уровни 0-1)

### 2.4 Выбор персоны

Спроси через `AskUserQuestion`: «Под какую из этих персон делаем адверториал?» Один адверториал = одна персона.

### 2.5 Уровни 0 и 1

Для выбранной персоны построй два уровня по методологии Ханта/Шварца — но НЕ строй остальные 3 уровня (Solution/Product/Most Aware), они не нужны для адверториала и тратят место.

**Level 0 — Unaware.** Человек не формулирует свою ситуацию как «проблему с названием». Язык бытовой, эмоциональный, часто вообще не про категорию продукта.

**Level 1 — Problem Aware.** Человек уже понимает, что что-то не так, гуглит и обсуждает симптом/боль, но не знает, что есть решение (или что решение — именно такого рода).

Для каждого уровня зафиксируй:

| Элемент | Что писать |
|---|---|
| Реальные цитаты (5-8) | Из Real Voices/Language Bank персоны (Fear Phrases в первую очередь). Мало сырья — добери целевым `WebSearch` по правилам из п. 2.2 |
| Психологическое состояние | Что думает, что делает, где (не) ищет |
| Боль | Максимально близко к цитатам, не абстракция |
| Триггер перехода на следующий уровень | Что сдвигает Unaware → Problem Aware, и Problem Aware → дальше (сам следующий уровень вне скоупа, но триггер — часто готовый хук) |
| Что важно услышать | Одна фраза-ориентир, как цитата |
| Посыл коммуникации | Не «продать» — конкретная задача: назвать категорию проблемы (L0) или снять «не знаю, что с этим делать» (L1) |

Не выдумывай цитаты и не сглаживай грубые/бытовые формулировки — сырой язык аудитории важнее гладкости. Часто «слишком просторечная для бренда» фраза и есть рабочий хук.

### 2.6 Две линзы на подачу (L0-L1)

Коротко зафиксируй, как эти уровни лягут в подачу — это не отдельный текст, а два угла, которые пригодятся на Шаге 4:

**Расчёт ценности предложения (что обещать):** на L0-L1 почти весь вес идёт на Dream Outcome — называем мечту/боль клиента её же словами, ничего пока не доказываем (доказательства — задача Credibility/Social Trust на Шаге 4, не этого шага).

**Структура подачи (как удержать внимание):**
- L0 — pattern interrupt: первые 3 секунды = зеркало боли аудитории, без упоминания бренда/продукта. Задача — только остановить скролл/чтение.
- L1 — базовая логика адверториала: Hook (называем то, что аудитория уже гуглит) → Agitate (усиливаем боль детальнее) → Educate (объясняем механизм/категорию) → Category reveal (вводим категорию решения, ещё не бренд) → Soft CTA (без давления).

### 2.7 Сводная боль уровней 0-1

Собери 1-2 предложения от первого лица.

Шаблон: «Я [состояние/симптом, Level 0], в последнее время ловлю себя на том, что [Level 1 — уже гуглю/пытаюсь разобраться], но не понимаю, [что именно решает эту ситуацию]».

## Часть C — Выбор метода

### 2.8 Метод(ы) разработки адверториала

Прежде чем идти на Шаг 3 (анализ продуктовой страницы) — реши, каким из пяти методов вытащишь боли персоны в текст. Это решение здесь, а не на Шаге 4, потому что оно определяет, что Шаг 3 должен искать на странице продукта.

| Метод | Когда выбирать | Что понадобится с Шага 3 |
|---|---|---|
| **1. Анализ FB Ads Library конкурентов** | Есть активные конкуренты, которые давно крутят рекламу (60-90+ дней) | Список конкурентных объявлений, их хуки/форматы |
| **2. Майнинг функций (Фича→Страх→Результат)** | Продукт технический/составной, у него понятный список фич/ингредиентов | Полный список фич/характеристик со страницы продукта |
| **3. Триггеры момента принятия решения** | В цитатах персоны явно виден момент «что случилось прямо перед покупкой» | Не требует данных со страницы — использует Шаг 2 напрямую |
| **4. Разрушение мифов** | В Language Bank персоны есть чёткое неверное убеждение, мешающее купить | Доказательства со страницы продукта, опровергающие миф |
| **5. Экспертный/образовательный угол** | Ниша, где экспертное мнение = разрешение купить (здоровье, финансы, уход) | Данные об эксперте/сертификатах/исследованиях со страницы |

Методы не взаимоисключающие — рабочий адверториал обычно сочетает 2-3. Основываясь на том, что реально нашлось на этом шаге (сильные ли триггеры в цитатах? есть ли явный миф? богата ли фича-база?), предложи 1-3 метода с коротким обоснованием и подтверди через `AskUserQuestion`.
